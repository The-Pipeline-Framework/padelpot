# PadelPot demo implementation plan

Authorization: the supplied brief explicitly instructs establishing a bounded credible plan and proceeding. No prior implementation or qualification was supplied. Qualification is performed first on the thinnest compiler-checked slice.

## Objective and scope
Four fictional owners use private chats to negotiate one doubles match through actual Gemma inference, with four explicit human approvals. One locally hosted Quarkus application, four isolated logical agents, an application-owned versioned persona store, and a static web chat adapter. No messaging SaaS, GPU requirement, authentication, booking, public profiles, generic agent platform, or framework modifications.

## Reuse and evidence
Pin TPF 26.9.4, Quarkus 3.39.2 and Java 21. Verify authoring against the exact v26.9.4 Git tag, rather than current main or the older 26.9.2 knowledge bundle. Use generated v3 contracts, provider-backed Query/Command, bounded recursive nested composition, regular service operations with Await completion, interaction-api correlation, memory orchestration, and native OTel/file replay. Application-owned Commands persist business state independently of TPF's orchestration stores.

## Execution topology
Every new owner channel request admits exactly one root execution. Polling, viewing, resets/fixture loading, Query/Command calls, nested agent turns, and owner completions admit zero new roots. Correlated human completions resume the existing root. HTTP ChannelAdapter is the sole authored PipelineExecutionService boundary. A named personal-agent nested pipeline loads a fresh minimal actor persona via Query, asks Gemma once via Query, validates inert output, applies authorized effects via Command, then either recurses or returns a review/result. Agent turns alternate the candidate and organizer within the same root. Await is unsupported inside nested definitions in this release; human reviews are therefore at the root's regular operation completion boundaries. One clarification and one final review are supported per request; additional ambiguity terminates cleanly and requires a fresh owner request. Framework recursion depth 10; offer exchanges stop at six turns; field inspection has an eight-action guard (at most nine model calls including the exhausted-guard pass); intent lifetime 15 minutes; one inference in flight; no hidden retries. Pending orchestration is attended single-process only and is lost on restart.

Thinnest slice: one request -> nested agent Query -> human Await -> Command -> result. Budget: exactly 1 root and one correlated resume. Final named `fourOwnersNegotiateAndLearn`: open + three find requests + one feedback request = exactly 5 roots. All approvals, clarification answers and persona-update approval are resumes. The verified 26.9.4 exporter produces native segment documents plus a shared Await control document. Retain these unchanged; assert native segment count = 5 + resume count, one control document, and exactly five root groupings with native execution IDs. This is the recorded application-level evidence adaptation. State reset must start with no pending requests; process restart is the demo reset for orchestration.

## Protocol and authority
Gemma emits one structured action (propose, counter, accept, decline, ask_owner, request_field, disclose) with proposed hour, style and court side. Trusted context is copied by TPF's completion envelope; a model cannot supply owner identity, request identity, version, authority, deadline or capacity. Only validated, whitelisted terms and policy-approved field values reach peers. Model explanation text is private owner output. Explicitly reject full-persona and private-field requests. Hard constraints and blocks override model actions. Unknown disclosure permissions prompt the owner. Soft preference compromises require permission when outside authorized flexibility. Organizer aggregate is the single capacity authority; atomic application Command checks expiry, versions, owner approval, compatibility, blocks and uniqueness. No court reservation is implied.

## Persona and interaction
Short conversational onboarding; inspect, correct and delete bounded application preferences. Field provenance distinguishes declared/inferred/observed. Corrections extracted by a model and post-match inferences become reviewable proposals; owner approval is required before persistence. Synthetic fixtures contain four minimal personas, broad Barcelona area, available hours and styles, preferred sides, and private canaries excluded from inference and peer messages. A channel-neutral owner/message/idempotency/interaction/answer contract powers the web adapter. UI presents independent chats, pending decisions and one match card; developer drawer shows permitted exchanges, policy decisions, checkpoints and execution IDs.

## Verification and recording
Pure invariant tests cover privacy, malformed proposals, malicious peer fields, blocks, expiry, cancellation, changed versions, duplicate/concurrent acceptance, capacity and update authorization. TPF integration checks topology, correlation, duplicates, wrong owner, and expiry. Fixture model is explicitly marked test-only; it does not count as real inference. Real Gemma scenarios check semantic outcomes without exact wording and may terminate unsuccessfully. The final proof uses the installed Ollama Gemma explicitly because OpenRouter access is not available in this environment. Default remote provider must fail closed without its key and enforce ZDR/data_collection deny/allow_fallbacks false. No automatic provider fallback.

## Risks, blockers and effort
OpenRouter key absent: remote integration cannot be exercised here. Ollama Gemma is available for the local real-model proof. Provider-native schema support and ZDR routing must be verified; unavailable strict privacy routing is an honest inference failure. Compile and topology are gates before UI expansion. Significant framework gaps stop implementation. Estimate: 1–2 focused agent-hours for the demo, plus live-inference variance and build dependency setup; this is an estimate, not a guarantee. Ordinary application adaptations: bounded persona/match JSON storage, domain connector, channel adapter, root-level human suspension, deterministic disclosure renderer. No framework expansion.
