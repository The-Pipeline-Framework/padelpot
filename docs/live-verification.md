## Corrections

Discovery now checks the selected match's fixed time against the owner's authority. If a compromise requires permission, a correlated question suspends the request before peer negotiation. The answer authorizes that time for the intent only: it neither changes the saved preference nor commits participation. Hard time boundaries cannot be overridden.

The app uses the published recursive parent-context fix in [TPF runtime #44](https://github.com/The-Pipeline-Framework/pipelineframework-runtime/pull/44). The runtime restores captured parent context before executor descent. PadelPot changes the dependency; it does not modify or bypass framework execution checks.

The tested runtime is **26.10.1-SNAPSHOT**, timestamped artifact **26.10.1-20261011.105237-12**, containing the fix from source commit `ccc16c5e6e13a1761f614275921e56f0a8b0d3e6`. Its packaged runtime JAR SHA-256 is `e726a79a26e9ddff39e6a4fe5f8e802d7189e9e5ba7c7f4c8287e46dd68d9935`. Snapshots are mutable; repeat live verification when updating them.

## Reproduction and local artifacts

Run `./scripts/reproduce.sh` with an exported `OPENROUTER_API_KEY` for the complete six-root scenario. Against a fresh server with an empty replay directory, `python3 scripts/e2e.py --match-only` verifies only the four match requests. The runner records every binding checkpoint and its pre-approval roster, and rejects any participation or confirmation without the corresponding owner reply.

`scripts/e2e-browser.mjs` exercises the real web chat against a fresh OpenRouter server. Install the optional Playwright tooling as shown in the README. It retains a screenshot and the actual correlated channel messages; it checks typed clarification, typed approval, delayed reviews, owner switching and the two-team roster. It rejects fixtures and preserves a failure recording instead of silently retrying.

This verification privately loaded the supplied `.env.local` key into isolated server environments. Credentials and generated output remain excluded from Git. Local recordings are under `output/real-gemma-20261011/`: the failed browser runs, the successful `browser-snapshot` recording and screenshot, the `full-flow-snapshot` execution dataset, unchanged native documents, owner conversations and the exact runtime fingerprint. The automated tests simulate owner gestures; they do not claim four independent humans or production messaging security. Gemma may still decline or exhaust its bounded turns in other runs.

Pending Await still uses process-local state, and the real-model probe did not test replay after storage changes or authenticated owner isolation.
