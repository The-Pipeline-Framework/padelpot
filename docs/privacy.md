# Privacy and authority in the demonstration

All people and preferences are synthetic. Logical agents share one application process. This does not demonstrate independent-device isolation, end-to-end encryption, production authentication or production-grade privacy.

Personas and accepted conversation turns are PadelPot business state, persisted by TPF's native aspect into the local H2 database. TPF execution state is separate. Only the currently acting agent receives its minimal player brief: level, broad area, authorized availability, preferred time/style/side and flexibility. The model also receives permitted match terms, bounded structured peer messages, selected earlier turns scoped to that owner, and the owner's bounded current request when that owner is acting (including a pending conversational question and its correlated answer). The Query reads at most 100 earlier turns and selects from newest to oldest under a conservative 16,384-token estimated window with 2,048 reserved for output. The budget includes fixed allowances for instructions and schema plus the known task, brief, terms, peer messages and current owner message. It is an estimate rather than a provider tokenizer guarantee. No full persona, private canary, exact address, telephone, health details, block list or private negative feedback field is sent. Owners should still avoid entering real sensitive data in this demonstration: their current request, selected prior turns and correlated conversational answer go to the configured inference provider.

A peer message cannot supply an identity, capability grant, deadline, persona version or human approval. Model text is untrusted. Only whitelisted structured terms and deterministically authorized field values become peer messages. Model reasoning is available in the synthetic developer activity view and never enters peer messages. That view can expose private reasoning; it is a local demo inspection tool, not an owner-isolated channel. A private field remains prohibited even if a model or peer requests permission to reveal it. Fields requiring permission create an owner checkpoint.

OpenRouter is the default. The host supplies `provider.zdr=true`, `data_collection=deny`, `allow_fallbacks=false` and `require_parameters=true` on every remote request, plus `store=false` and a 600-output-token bound. Routing requirements that cannot be met cause inference failure. There is no automatic switch to another provider or to test fixtures. These controls follow [OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection) and [ZDR documentation](https://openrouter.ai/docs/guides/features/zdr). They are provider policies, not proof that remote inference is fully private. Verify your account's own privacy settings. Prompts, bounded owner request/question/answer context and minimal preferences leave the application when remote inference is selected.

The optional Ollama build selects a local Gemma model explicitly through TPF's existing OpenAI-compatible Query integration and host ConnectionResolver. It has the same schema and token cap. The compatible Ollama request uses `reasoning_effort=none`, as described in [Ollama’s compatibility documentation](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx), so the bounded output budget is available for the decision. It does not use an OpenRouter key. The adapter performs one model inference per Query with no hidden retries or repair calls. TPF validates the canonical output; policy code validates allowed actions and binding decisions. Invalid output stops the execution or produces a safe decline.

An owner decides on a concrete review. TPF correlates their reply and resumes the owning execution. The channel adapter verifies the owner and attaches the native pending review as trusted context. The application Command then rechecks expiry, cancellation, current versions, blocks, hard preferences, approved flexibility, match terms, side capacity, player uniqueness and doubles capacity. Only the organizer's local match aggregate records commitments. Court booking is never performed.

Approved owner/match versions and accepted owner/agent turns persist to the local H2 database through TPF. Temporary intents stay in memory. Local access is limited by the operating system and localhost binding, without encryption. Pending TPF orchestration, Command effects and interactions use memory providers and are lost on restart. Historical root IDs may no longer be resolvable after restart. This is an attended local demo. A restart is not advertised as workflow recovery. Persona deletion erases that owner's stored revisions and persists the corrected current owner through TPF. The separate history erase Command removes that owner's saved turns; exported replay files and inference-provider data require separate handling. The demo's owner selector is not a production identity check. All exported demo evidence must be synthetic and reviewed for sensitive data.

The current reversible `TurnState` and `Review` persistence mappings also store their workflow fields, including the current owner text and peer transcript, alongside the approved visible turn. Keep the fixture fictional; a narrower write projection requires a persistence-contract change.

An active request may write a later turn after the history erase Command. The fixture does not fence those requests or provide a production erasure guarantee.
