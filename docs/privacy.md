# Privacy and authority in the demonstration

All people and preferences are synthetic. Logical agents share one application process. This does not demonstrate independent-device isolation, end-to-end encryption, production authentication or production-grade privacy.

Personas are versioned PadelPot business state, persisted by TPF's native aspect into the local H2 database. TPF execution state is separate. Only the currently acting agent receives its minimal player brief: level, broad area, authorized availability, preferred time/style/side and flexibility. The model also receives permitted match terms, bounded structured peer messages, and the owner's current message when that owner is acting. No full persona, private canary, exact address, telephone, health details, block list or private negative feedback field is sent. Owners should still avoid entering real sensitive data in this demonstration: their current chat message goes to the configured inference provider.

A peer message cannot supply an identity, capability grant, deadline, persona version or human approval. Model text is untrusted. Only whitelisted structured terms and deterministically authorized field values become peer messages. Model explanation text stays in the owner's chat. A private field remains prohibited even if a model or peer requests permission to reveal it. Fields requiring permission create an owner checkpoint.

OpenRouter is the default. The host supplies `provider.zdr=true`, `data_collection=deny`, `allow_fallbacks=false` and `require_parameters=true` on every remote request, plus `store=false` and a 600-output-token bound. Routing requirements that cannot be met cause inference failure. There is no automatic switch to another provider or to test fixtures. These controls follow [OpenRouter provider routing](https://openrouter.ai/docs/guides/routing/provider-selection) and [ZDR documentation](https://openrouter.ai/docs/guides/features/zdr). They are provider policies, not proof that remote inference is fully private. Verify your account's own privacy settings. Prompts, current owner messages and minimal preferences leave the application when remote inference is selected.

The optional Ollama build selects a local Gemma model explicitly through TPF's existing OpenAI-compatible Query integration and host ConnectionResolver. It has the same schema and token cap. The compatible Ollama request uses `reasoning_effort=none`, as described in [Ollama’s compatibility documentation](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx), so the bounded output budget is available for the decision. It does not use an OpenRouter key. The adapter performs one model inference per Query with no hidden retries or repair calls. TPF validates the canonical output; policy code validates allowed actions and binding decisions. Invalid output stops the execution or produces a safe decline.

An owner decides on a concrete review. TPF correlates their reply and resumes the owning execution. The channel adapter verifies the owner and attaches the native pending review as trusted context. The application Command then rechecks expiry, cancellation, current versions, blocks, hard preferences, approved flexibility, match terms, side capacity, player uniqueness and doubles capacity. Only the organizer's local match aggregate records commitments. Court booking is never performed.

Approved owner and match versions persist to the local H2 database through TPF. Chat history and temporary intents stay in memory. Local access is limited by the operating system and localhost binding, without encryption. Pending TPF orchestration, Command effects and interactions use memory providers and are lost on restart. Historical root IDs may no longer be resolvable after restart. This is an attended local demo. A restart is not advertised as workflow recovery. Persona deletion erases that owner's stored revisions and persists the corrected current owner through TPF. Historical chat or exported evidence must be removed separately. All exported demo evidence must be synthetic and reviewed for sensitive data.
